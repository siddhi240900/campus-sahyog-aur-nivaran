# CAMPUS सहयोग और निवारण

One digital platform for a connected and smarter college (Government Polytechnic Gulzarbagh).
**React 19 + Vite + Firebase (Auth, Firestore)**, also available as an **Android app** (Capacitor). Three roles: **Student**, **Faculty / Admin**, **Principal**.

## Features
| Area | What it does |
|---|---|
| Dashboard | Role-based overview: notices, today's routine, complaint statistics, approvals |
| Notices | Pinned notices targeted to everyone, a branch or a semester |
| Routine | Upload the routine as an **image** per branch + semester (replace any time), or add day-wise periods |
| Live resources | Free / occupied status of rooms, labs and halls, with release times |
| College chat | Global, branch and semester channels. Send **emojis, photos and PDFs** (photos show a small preview, tap to open the full file; PDF up to 3 MB) |
| Notifications | Bell with unread count, badges in the menu and a browser alert for new notices, chat messages, PaperPulse papers, complaint updates, QueueLess slots, routine changes and pending approvals (see below) |
| निवारण (Complaints) | Report problems with a photo; Pending → Assigned → In progress → Resolved; repeated-issue detection |
| गोपनीय शिकायत (Confidential) | Private complaints visible **only to the Principal** (and the reporter). The Principal sees who filed it (name, reg. no. / designation, branch) so the case can be resolved. Never shown in निवारण |
| QueueLess | Office service time slots for students |
| PaperPulse | Previous-year papers: attach the question paper as a **PDF or photos** (shown to students exactly as uploaded, never scanned), or type the topics, or paste text. Repeated-concept analysis runs on the topics |
| People & approvals | Students approved by branch faculty, faculty approved by the Principal |
| Student rules notice | Shown once after every student login |
| Android app | The same app packaged for Android with Capacitor (see *Mobile app*) |

## Tech stack
| Layer | Technology |
|---|---|
| Frontend | React 19, React Router 7, Vite 7 |
| Backend | Firebase Authentication + Cloud Firestore (security rules in `app/firestore.rules`) |
| Mobile | Capacitor 8 wraps the web build into an Android app |
| Files | Photos and PDFs are stored in Firestore in small pieces (no paid Storage plan) |

```

├─ README.md
└─ app/
   ├─ firestore.rules          Security rules (publish after every change)

   ├─ android/                 Android project generated by Capacitor
   ├─ src/
   │  ├─ main.jsx              Routes and providers
   │  ├─ config/               Constants: branches, categories, statuses, designations, theme
   │  ├─ context/              AuthContext (session, profile, role), NotificationContext (unread state and alerts)
   │  ├─ routes/guards.jsx     Route guards (login, approval, role)
   │  ├─ services/             All Firestore / Auth calls (data.js, users.js, auth.js, notifications.js)
   │  ├─ hooks/                useLive (live queries), useReveal, useGreeting (time-of-day greeting)
   │  ├─ lib/                  Pure helpers: format, image compression, paperFile / chatFile (PDF and photo attachments), people (name display), similarity, classifier, reporter
   │  ├─ components/           ui/ (Button, Modal, Tabs, StatusTrail…), layout/ (AppShell, AuthShell, NotificationBell, RulesNotice), chat/ (EmojiPicker, ChatAttachment), FileView
   │  └─ pages/                auth/, app/ (one file per feature), landing/
   └─ public/assets/           Logos (college logo and CAMPUS logos)
```
Rule of thumb: pages never call Firebase directly for writes; they use `services/`. Shared UI lives in `components/ui`.

## Run the website
All commands run inside the `app` folder.
```
cd app
npm install
npm run dev        # http://localhost:5173
npm run build      # production build into app/dist
```
Copy `app/.env.example` to `app/.env` and fill in the Firebase keys. `VITE_PRINCIPAL_UID` must equal `principalUid()` in `app/firestore.rules`.

## Mobile app (Android)
The Android app is **the same web app** inside a native shell, built with [Capacitor](https://capacitorjs.com). There is one code base: a change made for the website reaches the app after a rebuild.

**You need:** Node.js, Android Studio (with the Android SDK), and a phone with USB debugging on, or an emulator.

| What you want | Command (inside `app/`) |
|---|---|
| Open the project in Android Studio (then press Run) | `npm run android` |
| Build and run on a connected phone / emulator | `npm run android:run` |
| Only copy the latest web build into the Android project | `npm run build` then `npx cap sync android` |

`npm run android` is a shortcut for `npm run build && npx cap sync android && npx cap open android`.

Good to know:
- The app shows the files from the last `npm run build`. **After changing code, build and sync again**, otherwise the app keeps showing the old version. `npm run dev` only updates the browser.
- Firebase keys from `.env` are baked in at build time.
- **Share an APK:** Android Studio > Build > Build APK(s). The file is `app/android/app/build/outputs/apk/debug/app-debug.apk`.
- First time on a new computer after cloning: `cd app`, `npm install`, `npm run build`, `npx cap sync android` (the `android/` folder is already in the repository).
- Alerts work while the app is open. Push alerts when the app is closed need Firebase Cloud Messaging and Cloud Functions (paid Blaze plan), which this project does not use yet.

## Notifications
- **What:** new notices for you, chat messages in your channels, new PaperPulse papers, updates on your complaints (new complaints for staff), QueueLess slots assigned or changed, routine updates, replies on confidential complaints (details are never shown), and people waiting for approval (faculty / Principal).
- **How it works:** `services/notifications.js` lists, per role, a few small Firestore queries (newest 10 each). `context/NotificationContext.jsx` watches them, keeps what you have already seen on this device (`localStorage`) and raises a popup, or a browser notification when the tab is in the background and you tapped "Turn on" in the bell panel. Opening a feature page marks it as read; in chat each channel is marked as you read it.
- **Limit:** alerts work while CAMPUS is open (in a browser tab, also in the background, or in the app). Alerts when it is fully closed need Firebase Cloud Messaging plus Cloud Functions (paid Blaze plan).
- **Cost:** about 60 document reads per login for these feeds. Keep an eye on the Firestore free quota if many users log in daily.
- To add a new kind of notification, add one feed in `feedsFor()` and one entry in `NOTIFICATION_GROUPS`.

## Branches
All branches live in one list, `app/src/config/branches.js`. Every screen (register, approvals, notices, routine, chat, QueueLess, PaperPulse) reads from it, and `firestore.rules` does not restrict branch ids. To add a branch, add one line `[id, 'Full name', 'Short name']` at the end of the list; keep existing ids unchanged because they are stored in user and paper records.

## One-time Firebase setup
1. Authentication > Sign-in method: enable Email/Password.
2. Firestore > Rules: paste `app/firestore.rules` and **Publish** (repeat after every update of the file).
3. Create the Principal in Authentication > Users, put its UID in `app/firestore.rules` and `app/.env`, then log in once. The profile is created automatically.

## Account flow
- Student: register, verify email, a faculty member of the same branch approves, then access.
- Faculty/Admin: register, verify email, the Principal approves, then access.
- Faculty with branches approve students of those branches; faculty with no branch can approve every branch.
- Login lasts only while the browser tab is open. Registration numbers are unique (`regNumbers`).

## Security notes
- All authorization is enforced in `firestore.rules`, not in the UI. The Principal is identified by UID only.
- Confidential complaints: only the Principal and the reporter can read them; the stored reporter name/role is validated against the reporter's real profile, so nobody can file under another person's name.
- Chat photos / PDFs are stored in pieces under `chats/{channel}/files` (same channel rules as messages; only staff can delete). PaperPulse files are stored in pieces under `papers/{id}/files`; only faculty can write them, active users can read them. PDF is limited to 5 MB and 5 files per paper.
- Complaint, routine and photo sizes are limited in the rules. Images are compressed in the browser and stored in Firestore (no paid Storage).
- Never commit `.env`, `local.properties`, or any signing key (`*.jks`, `*.keystore`). No AI key belongs in the browser; use your own endpoint via `VITE_AI_ENDPOINT` (`app/src/lib/ai.js`).

## Conventions
- Dashboard greeting follows the device clock (morning / afternoon / evening) and updates by itself; it shows the user's full name.
- Show a person's name through `displayName()` in `app/src/lib/people.js`, so the Principal always appears with the "Principal" salutation.
- Components `PascalCase.jsx`, helpers/hooks `camelCase.js`; one page per feature in `pages/app/`.
- Colours only through `app/src/config/theme.js` / CSS variables in `styles.css`.
- Commit messages follow `type(scope): summary` (`feat`, `fix`, `refactor`, `docs`, `chore`, `style`).
